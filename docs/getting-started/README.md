# Getting started

Five short pages, meant to be read in order the first time a team adopts
inhousecode. Each one ends where the next begins.

1. [Install it](01-install.md) — get the `inhousecode` command working.
2. [Run your first review](02-first-review.md) — see it work, with nothing
   installed into git yet.
3. [Write your first rule](03-first-rule.md) — turn one comment your team
   keeps repeating into something the reviewer enforces.
4. [Turn on the hook](04-turn-on-the-hook.md) — wire it into `git commit` or
   your agent's stop event.
5. [Roll it out to the team](05-roll-out-to-the-team.md) — the order that
   doesn't get the gate uninstalled in week two.

If you just want the "why" before any of this, read
[docs/concept.md](../concept.md) first. If you want the full reference
instead of the guided version, the [README](../../README.md) and
[docs/configuration.md](../configuration.md) /
[docs/team-customization.md](../team-customization.md) have it.
